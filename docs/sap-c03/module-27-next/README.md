Review-only question drafts. Not part of the live 28-question diagnostic or any timed form. Do not enable an item until its technical accuracy, visual, and teach-back links have passed review.

## Make a case genuinely new

- Change at least one decision-making constraint (e.g. service-only vs broad routing, overlap, recovery window, writer coordination, or operations control). A new company name and shuffled options are not a new case.
- Show how an otherwise valid near-miss violates a named constraint. Keep only one defensible answer set, use an explicit selection count, and validate each choice against first-party sources.
- Give immediate feedback in practice mode only. The answer visual should show the relationship that decides the case, not reproduce the entire explanation.
- Link to specific existing lessons, not just a module landing page. Practice mode can show those links after checking; timed-mode links are shown only after submission.
- Reserve completely separate scenario families for the scored readiness forms. Do not recycle previously shown stems as unseen items. Separate a 28-question diagnostic from a 75-question full mock when the review gate passes.

The companion validation metadata records the pinned source commit and exact teach-back blob references. Missing answer artwork is a reason to hold a question, not a reason to use a template chart or silently omit the feedback.

The optional practice section in this branch includes all five cases: overlapping networks and PrivateLink, IAM Roles Anywhere, gp3 throughput, a verified DataSync cutover, and CloudFormation Hooks. Each shows its own raster and option-by-option explanations only after the learner checks the required number of choices. The exact lesson links lead back to the instruction. These cases are deliberately excluded from both the diagnostic score and any future unseen readiness form.
