# SAP-C03 Module 27: diagnostic and mock forms

This change adds an opt-in form helper. It intentionally makes no question-bank, renderer, engine, or production availability change.

- **Existing diagnostic:** retain exactly the original 28 questions in original order, original options/images, untimed practice or the current 90-minute diagnostic. Never move old diagnostic answers onto shuffled choices. Leave schema-1 storage intact.
- **Review before publishing:** the release bank must contain an independently reviewed answer key, five valid SAP-C03 domains as strings, distinct scenario stems, original content, credible alternatives, a technical explanation, and a verified mapped visual for each item. Set `reviewStatus: "reviewed"` only after those checks. Current diagnostics without this marker do not count toward full mock availability. Leave drafts out of the production bank. Generic validators cannot verify technical correctness, semantic near-duplicates, file existence, course placement, or actual coverage of every objective; reviewers must verify all separately. Record the objective, first-party service references, image provenance, correct rationale and distinct reasons plausible distractors fall short. Avoid option-letter references and “all/none of the above”; if an intentionally ordered authoring pattern is unavoidable, opt out for that item with `preserveChoiceOrder: true`.
- **Release gates:** only render the full mock Start action if the reviewed bank satisfies `assessFullMock(bank).available`. It needs at least 75 unique valid reviewed items and scored-domain counts at least **16 / 16 / 10 / 10 / 13**. These quotas apply largest-remainder rounding to 65 scored slots at 25/25/15/15/20. Ten remaining reviewed items are unscored and interspersed; ready the gating count alone does not make an official AWS exam or resolve remaining domain objective gaps. The reporting denominator for a full timed rehearsal is 65. Do not display unscored item markers before submission and do not convert raw practice percentages to AWS scaled scores or official pass/fail.
- **Determinism:** use a fresh seed, e.g. `crypto.randomUUID()`, only when beginning a new full timed form. Persist the schema-2 attempt and entire form descriptor under a new key; this includes the display order, scored map, content fingerprints, and per-item option permutation. Use `hydrateForm(saved.form, bank)` on restore, not a newly shuffled form. An edited/removed question or invalid permutation fails closed; explain the old attempt cannot be regraded instead of silently changing answers. Bump optional `revision` when a same-path image or other meaningful content changes.
- **Compatibility:** `createDiagnosticForm(legacy28, mode)` accepts the fully mapped original bank (including stable M27 image paths) and yields unchanged order. For future full forms, use `startFormAttempt(form)`, not legacy engine `startAttempt` (the old function is intentionally fixed to 28). Existing `answer/checkAnswer/flag/advanceTime/submit` reducers operate on the form's displayed questions and retain extra runtime properties. Preserve the schema-2 descriptor in UI reducer typing and persistence, and call `scoreForm(attempt, form)` for full mock results rather than legacy `score`, which scores every displayed item. Keep an absolute deadline and apply `advanceTime` at restore and each mutation. Key the navigation by stable question IDs; save current question ID separately for resume; use display position only as a label. Restore safely on localStorage exceptions.
- **Presentation:** practice reveals explanations once checked. Timed modes show explanations, image/diagram, each option's rationale and the matching course link only after submission/expiry. Label all course practice as original. Preserve 28 visual paths and verified media files; for expanded practice show visuals only when mapped and verified.

Primary sources: [SAP-C03 guide, response and scoring format plus domain weights](https://docs.aws.amazon.com/aws-certification/latest/solutions-architect-professional-03/solutions-architect-professional-03.html) and [AWS certification page, question count and duration](https://aws.amazon.com/certification/certified-solutions-architect-professional/).

Targeted tests: `node --test tests/sap-exam-forms.test.mjs` in the repository, or set `SAP_LEGACY_BANK_PATH` to an existing checkout's `app/components/sap-exam/questions.json` when the new helper is being tested from a separate staging directory.
