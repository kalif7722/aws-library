11. EL10 SECTION STANDARD — 16 TO 20 SECTIONS
==================================================

Each GCP EL10 visual should normally contain:

MINIMUM:
16 meaningful sections

TARGET:
16–18 sections for most services

MAXIMUM:
20 sections for complex services

Do not exceed 20 sections unless there is a genuinely exceptional technical reason.

The objective is NOT to maximize section count.

The objective is to provide:

- complete conceptual coverage
- clear architecture understanding
- high readability
- useful diagrams
- balanced visual density

Prefer fewer strong sections over many tiny panels.

--------------------------------------------------
RECOMMENDED EL10 STRUCTURE
--------------------------------------------------

Adapt intelligently per service.

1. SERVICE INTRODUCTION
What the service is, its purpose and the problem it solves.

2. SERVICE AT A GLANCE
Key capabilities and where it fits within GCP.

3. CORE CONCEPTS
Essential terminology and constructs.

4. HOW IT WORKS
High-level operational model.

5. ARCHITECTURE / REQUEST FLOW
End-to-end visual architecture showing users, applications, dependencies and flow.

6. KEY COMPONENTS / DATA MODEL
Important internal objects, resources or entities.

7. SCALING / PERFORMANCE / CAPACITY
Scaling model and workload behavior.

8. AVAILABILITY / RESILIENCE
Regional/zonal behavior, HA, replication, durability and failover where relevant.

9. ADVANCED CAPABILITIES
Important service-specific capabilities not already covered.

10. SECURITY & IAM
Permissions, encryption, boundaries, network/security controls.

11. MONITORING & OPERATIONS
Logging, metrics, alerts, observability and management.

12. INPUTS / OUTPUTS / COMMON OPERATIONS
Typical ways applications interact with the service.

13. INTEGRATIONS
Important related GCP services.

14. PRICING / COST FACTORS
Main cost drivers and optimization considerations.

15. COMMON USE CASES / APPLICATION FIT
Best workload fit and common scenarios.

16. BEST PRACTICES & WATCH POINTS
Recommended design practices, limitations and common mistakes.

17. TROUBLESHOOTING
Use when operational troubleshooting materially improves understanding.

18. RELATED SERVICES / ALTERNATIVES
Related GCP services and key decision differences.

19. DESIGN DECISIONS / WHEN TO USE
When this service should or should not be chosen.

20. EL10 TAKEAWAY / LEARNING WORKFLOW
Concise visual summary tying the service together.

Do not force all 20 sections.
